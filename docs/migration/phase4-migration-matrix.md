# Phase 4 migration matrix (shadcn/ui, family by family)

Phase 5 (docs/migration/phase5-specialised-components.md) protects the specialised components (searchable Select, PhoneNumberInput, QidInput, SignaturePad, DataTable, Tooltip, notifications) and removed the unused shadcn Select, Tooltip and Sonner; the shadcn components left in `src/components/ui/` are button, card, checkbox, input, label, textarea (migrated) and dialog (Phase 6: Modal and Drawer), tabs (Phase 7: TabStrip and SegmentedTabs) and dropdown-menu (deferred, unused).

**Release status of each family is in docs/migration/release-gate.md (the authoritative gate matrix); the Status columns below are the per-phase record.** Phase 7 (docs/migration/phase7-tabs-dropdown.md): the tab strips are Radix Tabs; the Dropdown Menu has no standard consumer (deferred). Phase 6 (docs/migration/phase6-overlays-select.md): Modal and Drawer (13 + 24 files) are now the Radix Dialog through their unchanged wrappers; the standard Select has no eligible usage and the searchable Select is retained.

Status values: Not started, Audited, Ready, In progress, Migrated, Validated, Blocked, Reverted, Complete. Risk: Low, Medium, High, Deferred.
Evidence for every family gate: `tsc -b`, `oxlint`, `npm test`, `npm run build`, and Playwright (`npm run test:e2e`, desktop / tablet / mobile x light / dark):
`e2e/sweep.spec.ts` (20 screens + the UI Components Library, one pixel snapshot and one accessibility-tree snapshot each, taken BEFORE the family's change and compared AFTER it),
`e2e/enterpriseAccountCreation.spec.ts` (Phase 3 pilot, with axe), `e2e/checkbox.spec.ts`.

## Design decision for Phase 4 (recorded so it can be reviewed)
The shadcn **Label** and **Card** were made presentation-neutral (Label = bare label, Card = the app's `card` class only). Phase 1 had them carry
`field-label` / `flex flex-col gap-3 py-4 text-card-foreground`, which would have changed 112 existing elements. With the neutral base a migrated
element renders the same class list as before (checked by an AST comparison of every converted element against git HEAD: 673 of 676 token-identical,
the other 3 are an attribute that became redundant) and the call site keeps choosing its own look. The Phase 1 contract test in
`tests/uiShowcase.test.mjs` was changed to say so (it now asserts neutrality), not weakened.

## Deferred / retained usages and why
- **Labels not converted (13):** inside Select (excluded), QidInput, ContactPhoneInput, ServiceLocationSearchInput, CompanySearchInput (domain inputs), Sidebar / PersonaSwitcher (navigation), CafSignatureCapture, MsisdnPicker (specialised).
- **Cards not converted:** 58 non-`div` elements (`section` 29, `aside` 5, `dl` 5, `p` 5, `button` 4, `ul` 3, `li` 2, `span` 2, `label` 2, `Link` 1 - the shadcn Card is a `div`, so they keep the `.card` class), 5 `div`s whose class is conditional or whose component is excluded (`BillLimitEditor`, `TopicFieldsSection`, `CafSignatureCapture`, `CustomerActionsMenu`, ...), and class lists held in constants.
- **Buttons not touched:** 146 hand-written `<button>` elements (link-styled, row actions, carousels, ...) - none carries `btn` classes; `CloseButton`; the stock `ui/dialog` that imports the Button.
- **Inputs not touched:** `SearchField`, the login fields (`login-field`, a different look), `QidInput`, `PhoneNumberInput`, `ContactPhoneInput`, `Select`'s search input, the sidebar menu search, file inputs, the addon branch of `Input`.
- **Compatibility adapters:** Checkbox `onChange(e => ...e.target.checked)` -> `onCheckedChange(checked => ...(checked === true))` at 16 sites; OrderConfirmationScreen maps its own `'primary' | 'secondary'` to the Button variants; TicketsDashboard's select column carries `align-[1px]` (a button's baseline sits 1px lower than the old inline wrapper in a table cell).

## Decision needed: Tabs and Dropdown Menus
The installed shadcn `tabs.tsx`, `dropdown-menu.tsx` and `dialog.tsx` are not themed (Phase 1 themed button, input, label, card and checkbox; the unused select, tooltip and sonner were removed in Phase 5), so the "already-themed" precondition is not met for Family 5. Even themed, Radix Tabs cannot reproduce the app's strip exactly: it adds PageUp/PageDown, makes the list itself a tab stop, activates on mouse-down (the app on click), emits `aria-controls` pointing at a panel the app does not render (an override is possible) and an extra wrapper element. The app's own strip is a small, correct WAI-ARIA implementation with its keyboard contract pinned by tests. Recommended: keep it, or approve the additive Radix behaviour and the theming work as its own phase. The two dropdown-like menus are domain/navigation components with business logic (persona navigation, journey launch, drawer fallback), excluded by scope.
